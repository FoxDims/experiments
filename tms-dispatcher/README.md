# SmartTransport — рабочее место диспетчера

Интерактивный прототип B2B-системы управления городским автобусным транспортом (Рязань).
Сценарий: поломка автобуса на маршруте № 10 и его замена резервным бортом.

## Как открыть

**С Яндекс Картами (основной вариант) — GitHub Pages:**

1. Settings → Pages → Source: *Deploy from a branch*, ветка `claude/tms-dispatcher-dashboard-nabx0j` (или `main` после слияния), папка `/ (root)`.
2. Прототип откроется по адресу `https://foxdims.github.io/experiments/tms-dispatcher/`.
3. В кабинете [developer.tech.yandex.ru](https://developer.tech.yandex.ru) у ключа JavaScript API
   укажите ограничение по HTTP Referer: `foxdims.github.io` и, для локальной работы, `localhost`.

Локально: `python3 -m http.server` в корне репозитория → `http://localhost:8000/tms-dispatcher/`.
С `file://` Яндекс Карты могут не загрузиться из-за проверки домена ключа.

Ключ лежит в `config.js`. Ключ JS API всегда виден в коде страницы, его защищает ограничение по доменам.

**Без Яндекс Карт.** Если API недоступен (нет ключа, домен не разрешён, страница открыта артефактом),
прототип сам переключается на собственную векторную схему Рязани.

## Карта

- Leaflet рисует данные: маршруты, автобусы, эффекты аварии. Он работает в проекции EPSG:3395, как Яндекс,
  поэтому слои совпадают с подложкой без смещения.
- Под Leaflet лежит синхронизированная карта Яндекса (JS API 2.1) без собственных элементов управления.
  В тёмной теме подложка инвертируется CSS-фильтром (`--ym-filter`), в светлой — приглушается.
- Трассы маршрутов — реальные, из `data/routes.json`. Если данных нет, используется схема,
  а трассы строятся геокодером и маршрутизатором Яндекса по опорным точкам (`ROUTE_NODES`).
- Улица в карточке аварии определяется обратным геокодированием Яндекса.
- При аварии маршрутизатор считает реальные пути и время доезда резервных бортов (с учётом пробок).

## Что внутри

- **Экран 1 — оперативная карта.** Состояние покоя: KPI в шапке, карта с маршрутами,
  автобусами и резервом, лента событий и список маршрутов.
- **Состояние аварии.** Наступает через 10 с или по кнопке «Поломка сейчас». Срабатывают
  баннер над картой, карточка в ленте, пульсация на карте, красный маршрут 10, счётчики и звук.
- **Экран 2 — окно замены.** Данные сломанного борта, ранжированный резерв с причинами
  и рисками, влияние на интервалы, кнопка «Назначить на маршрут». Затем статус выполнения
  и 10 секунд на отмену.
- **UX-логика.** Иконка книги в левом меню: User Flow, тайминг, цветовая система, логика рекомендаций.

Горячие клавиши: `Enter` — решить / назначить, `1–4` — выбор кандидата, `Esc` — закрыть, `/` — поиск.

## Сборка

Исходник — `src/index.src.html`. Команда `python3 build.py <leaflet.css> [fragment.html]`
встраивает CSS Leaflet и собирает `index.html` (при необходимости — ещё и фрагмент для публикации артефактом).

## Данные маршрутов

Трассы и остановки взяты с bus62.ru: `tools/extract_bus62.py` разбирает HAR-записи сайта
(и сохранённые ответы `getRouteNodes`) в `data/routes.json`, сборка вшивает его в страницу.
Прототип берёт маршрут 10 и шесть маршрутов с наибольшим общим участком с ним.
Госномера и позиции реальных автобусов не сохраняются. Бортовые номера, водители, резерв
и отклонения от графика смоделированы.

```
python3 tools/extract_bus62.py data/routes.json bus62.ru.har "10=route10-484.json,route10-485.json"
```
